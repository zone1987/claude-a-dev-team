## Concept: `sw-context-token`

The `sw-context-token` is the central session identifier in the Shopware Store API. It identifies:
- The user's **cart**
- The **logged-in customer** (or guest)
- The selected **currency, language, payment method, shipping method**
- The active **shipping addresses**

The token is generated by the server on the first request and returned as the response header `sw-context-token`. On every further request it must be sent along as the request header `sw-context-token`.

```ts
import { useSessionContext } from '@shopware/composables'

const ctx = useSessionContext()

const ctx = useSessionContext(initialSalesChannelContext)
```

## Token persistence: cookie-based pattern

### Vanilla Vue (without Nuxt)

```ts
// plugins/shopware.ts
import { createAPIClient } from '@shopware/api-client'
import { createShopwareContext } from '@shopware/composables'
import Cookies from 'js-cookie'

const TOKEN_COOKIE_NAME = 'sw-context-token'

export default (app: App) => {
  const contextToken = Cookies.get(TOKEN_COOKIE_NAME)

  const apiClient = createAPIClient({
    baseURL: import.meta.env.VITE_SHOPWARE_ENDPOINT,
    accessToken: import.meta.env.VITE_SHOPWARE_ACCESS_TOKEN,
    contextToken,  // load from the cookie on startup
  })

  // persist the token whenever it changes
  apiClient.hook('onContextChanged', (newToken: string) => {
    Cookies.set(TOKEN_COOKIE_NAME, newToken, {
      expires: 365,
      sameSite: 'strict',
      secure: location.protocol === 'https:'
    })
  })

  createShopwareContext(app, { apiClient })
}
```

## SSR-safe token handling in Nuxt

The decisive problem with SSR: the `apiClient` is a **singleton** per request — not a global singleton. Otherwise all concurrent server requests share the same context token (session leak).

### How `@shopware/nuxt-module` solves it

The Nuxt plugin (`plugin.ts`) creates a new `createAPIClient` instance per request:

```ts
// Internally in the @shopware/nuxt-module plugin.ts (simplified)
export default defineNuxtPlugin((nuxtApp) => {
  const runtimeConfig = useRuntimeConfig()
  const shopwareConfig = runtimeConfig.public.shopware as ShopwareNuxtOptions

  // SSR: use the private endpoint if configured
  const isSSR = import.meta.server
  const baseURL = isSSR
    ? (runtimeConfig.shopware?.endpoint ?? shopwareConfig.endpoint)
    : shopwareConfig.endpoint

  // read the cookie from the current request (H3 + useRequestEvent)
  const contextTokenCookie = useCookie<string>('sw-context-token', {
    maxAge: 60 * 60 * 24 * 365,
    sameSite: 'strict',
    secure: true,
  })

  const apiClient = createAPIClient({
    baseURL,
    accessToken: shopwareConfig.accessToken,
    contextToken: contextTokenCookie.value ?? undefined,
  })

  // write token changes into the cookie
  apiClient.hook('onContextChanged', (newToken: string) => {
    contextTokenCookie.value = newToken
  })

  // handle maintenance mode
  apiClient.hook('onResponseError', (response) => {
    if (response.status === 503) {
      // show the maintenance page
    }
  })

  // provide it to the Vue app
  createShopwareContext(nuxtApp.vueApp, {
    apiClient,
    devStorefrontUrl: shopwareConfig.devStorefrontUrl,
    cacheableReads: shopwareConfig.cacheableReads,
  })
})
```

### Nuxt configuration

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@shopware/nuxt-module'],

  shopware: {
    endpoint: 'https://shop.example.com/store-api',
    accessToken: 'SWSCXXXXXX',

    // Optional: separate SSR endpoint (e.g. internal network)
    // → is set as runtimeConfig.shopware.endpoint (private)
    // the CSR endpoint stays in runtimeConfig.public.shopware.endpoint

    devStorefrontUrl: 'https://shop.example.com',  // for admin links in dev mode
    apiClientConfig: { timeout: 10000 },
    useUserContextInSSR: false,   // do not use the user context (login) during SSR
    cacheableReads: false,        // cache GET requests
  },

  runtimeConfig: {
    // private (SSR-only) configuration
    shopware: {
      endpoint: process.env.NUXT_SHOPWARE_ENDPOINT,  // internal API endpoint
    },
    public: {
      // client-side configuration
      shopware: {
        endpoint: process.env.NUXT_PUBLIC_SHOPWARE_ENDPOINT,
        accessToken: process.env.NUXT_PUBLIC_SHOPWARE_ACCESS_TOKEN,
      }
    }
  }
})
```

## Switching currency / language

```ts
const { setCurrency, setLanguage, currency, salesChannelLanguageId } = useSessionContext()

// switch the currency
await setCurrency({ id: 'eur-uuid' })
// → sends PATCH /context with { currencyId }
// → the response contains a new sw-context-token
// → sessionContext is updated automatically

// switch the language
await setLanguage({ id: 'de-DE-uuid' })
// → sends PATCH /context with { languageId }
```

## Reading the current context value directly

```ts
const { sessionContext, currency, taxState, userFromContext } = useSessionContext()

// currency
console.log(currency.value?.isoCode)   // "EUR"
console.log(currency.value?.symbol)    // "€"

// tax indication
console.log(taxState.value)            // "gross" or "net"

// logged-in user (null when logged out, undefined when not yet loaded)
console.log(userFromContext.value?.email)
```

## Pattern: refresh the context after login

After login the context token changes (the new token carries the customer session). `useUser.login()` internally passes the new token through via `onContextChanged`.

```ts
const { login } = useUser()
const { refreshSessionContext } = useSessionContext()

async function handleLogin(email: string, password: string) {
  await login({ username: email, password })
  // the token was updated automatically via onContextChanged
  // reload the context to get the customer data:
  await refreshSessionContext()
}
```

## Pattern: language header for multilingual shops

```ts
// in the createAPIClient setup:
apiClient.defaultHeaders['sw-language-id'] = cookieLanguageId.value

// when the language is switched:
apiClient.hook('onDefaultHeaderChanged', (headerName, value) => {
  if (headerName === 'sw-language-id') {
    cookieLanguageId.value = value as string
  }
})
```

## Typical initialization sequence (complete)

```
a browser request arrives
  ↓
Nuxt plugin (per request):
  1. read the context token from the cookie
  2. create createAPIClient({ contextToken })
  3. onContextChanged hook: write the token into the cookie
  4. createShopwareContext(app, { apiClient })
  ↓
the first page renders:
  5. call useSessionContext().refreshSessionContext()
     → GET /store-api/context
     → response header: sw-context-token (possibly new)
     → onContextChanged fired → cookie updated
     → sessionContext.value set
  ↓
user interaction:
  6. useCart().addProduct() → POST /store-api/checkout/cart/line-item
     → response header: sw-context-token (same or new)
     → processed automatically by defaultHeaders
```
