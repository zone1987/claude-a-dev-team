# Project Zomboid dedicated server

The dedicated server is the same engine with the client half switched off. It is administered three
ways, and picking the right one is most of the work: **in-game admin commands**, **RCON** from
outside the game, and **the config files** it reads at boot.

## What every server task needs

- **Access levels gate everything.** A command carries a required capability, and a player without it
  gets a refusal rather than an error. The levels are hierarchical, with `admin` at the top.
- **The config lives in the save folder, not the install.** On this machine that is under
  `~/Zomboid/Server/` — the INI, the sandbox variables and the spawn regions are separate files, and
  changing the install directory does nothing.
- **RCON is a separate listener** with its own port and password from the INI. It executes the same
  commands an admin types in game, so anything below is reachable from outside.
- **The server is authoritative.** A command changes server state and the change propagates; the
  reverse is not true.

## Reference map

- **[references/ADMIN-COMMANDS.md](references/ADMIN-COMMANDS.md)**: every server command — 68 command classes, 67 carrying a command name — with its exact command string, arguments, required capability and behaviour. Generated from the game's own classes, so the spellings are exact.
- **[references/SERVER-OPTIONS.md](references/SERVER-OPTIONS.md)**: all 144 server INI options with their type, default and meaning, generated from `zombie.network.ServerOptions`.
- **[references/SAVEGAME-FORMAT.md](references/SAVEGAME-FORMAT.md)**: the on-disk save format — every file and folder in the save with the class that writes it, the chunk and fog-of-war binary layouts, the `id_manager_data.bin` counter trap, corpse-removal semantics, and what actually drives start and backup cost. Verified against decompiled bytecode; the unverified gaps are marked as such.

## Reaching the server from outside

Two channels, and they answer different questions:

- **RCON** for doing things: run any admin command, get its text output back. Synchronous, and it
  needs the port open and the password held by the caller.
- **The files the server writes** for observing things: the logs record what happened, and the save
  folder holds durable state. A consumer that tails a log survives a server restart, which a
  connection does not.

### Reaching a hosted server's filesystem

A rented server is usually only reachable over FTP. `scripts/pz_ftp.sh` in this plugin wraps that:
`check`, `ls`, `get`, `put` (with byte-for-byte verification), `tail` for the end of a large log, and
`logs` to pull `server-console.txt` plus every `Logs/*.txt` in one go.

Credentials come from `PZ_FTP_HOST` / `PZ_FTP_PORT` / `PZ_FTP_USER` / `PZ_FTP_PASS` (falling back to
the unprefixed `FTP_*` names a host panel often provisions). **Their values are never printed, never
passed as command arguments, never written to a file and never committed** — the script hands them to
curl through `--config` precisely so they stay out of `ps` and shell history.

**Write only to a stopped server.** A running server holds save state in memory and overwrites files
on its next save, so an upload lands and then silently vanishes.

For pushing game events outward, a mod writes and something outside reads — call the Skill tool with
`pz-multiplayer` for what a mod can actually write, and with `pz-events` for what it can react to.

## Adding your own command

A custom command is server-side Lua reacting to a client message, not a new RCON verb: the RCON
surface is fixed by the Java classes. The mechanism is `sendClientCommand` from the client and an
`OnClientCommand` handler on the server; `pz-multiplayer` carries the exact signatures and the
supported argument types. Where a genuinely new admin verb is needed, the honest answer is that it
goes through an existing command or through a file, not through RCON.

## Source

Distilled from Project Zomboid build **42.20.2** (revision `ffe7a8a4b1`), installed at
`~/Library/Application Support/Steam/steamapps/common/ProjectZomboid/Project Zomboid.app/Contents/Java`,
retrieved 2026-08-26. `ADMIN-COMMANDS.md` is generated by `scripts/parse_admin_commands.py` and
`SERVER-OPTIONS.md` by `scripts/parse_server_options.py`, both from `projectzomboid.jar`.

`SAVEGAME-FORMAT.md` was written by hand from `projectzomboid.jar` decompiled with CFR 0.152, and
every layout in it was cross-checked byte-for-byte against a live dedicated-server save. It is not
generated, so a new build needs it re-verified rather than re-run.

The game's own files are the primary source; the API is cross-checked against the build 42 JavaDocs at <https://projectzomboid.com/modding/index.html> and the unofficial build <https://github.com/demiurgeQuantified/ProjectZomboidJavaDocs>.
