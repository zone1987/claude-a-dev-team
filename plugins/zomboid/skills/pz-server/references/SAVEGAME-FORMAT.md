# Savegame format (build 42)

Verified against decompiled `projectzomboid.jar` (build 42.20.2, CFR 0.152) and cross-checked
byte-for-byte against a live dedicated-server save. Class, method and formula are named for every
claim. Anything not verified is marked as such — do not fill those gaps from memory.

The save folder is `<cacheDir>/<gameMode>/<gameSaveWorld>/`, e.g. `~/Zomboid/Saves/Multiplayer/servertest/`.
On a dedicated server the world name comes from `-servername`, so the folder is usually `servertest`.

## Folder and file map

| Path | Written by | Holds |
|---|---|---|
| `map/<X>/<Y>.bin` | `ChunkMapFilenames.getFilename(int,int)` | One **chunk**. X/Y are chunk coordinates; `CHUNK_DIM = 8` squares per chunk edge. `chunkX = squareX / 8` |
| `chunkdata/chunkdata_<a>_<b>.bin` | `MapCollisionData` (**native**, `SavefileNaming.SUBDIR_CHUNKDATA`) | Per-chunk collision bits for pathfinding (`BIT_SOLID`, `BIT_WALLN`, `BIT_WALLW`, `BIT_WATER`, `BIT_ROOM`) |
| `zpop/zpop_<a>_<b>.bin` | `MapCollisionData` (**native**, `SUBDIR_ZPOP`) | Zombie population data per cell |
| `apop/apop_<a>_<b>.bin` | `AnimalCell.save()/load()` (**pure Java**) | Animal population per cell; the class computes `x*256`/`y*256` for square base, `x*32`/`y*32` for chunk base |
| `isoregiondata/datachunk_<x>_<y>.bin` | `IsoRegions` (`FILE_PRE="datachunk_"`, `FILE_DIR="isoregiondata"`) | IsoRegion pathfinding/line-of-sight structure, streamed to clients |
| `metagrid/metacell_<x>_<y>.bin` | `IsoMetaGrid` partials (`SUBDIR_METAGRID`) | Metagrid per-cell data, separate from `map_meta.bin` |
| `map_meta.bin` | `IsoMetaGrid.load()` / `.save()` | Building and room metadata per cell (`buildingByMetaId`, `roomByMetaId`) |
| `map_zone.bin` | `IsoMetaGrid.loadZone()` / `.saveZone()` | Zone definitions; `"ZONE"` header check in `loadZone` |
| `map_t.bin` | `GameTime`, `IsoCell`, `IsoWorld`, `GameServer` | World time. Magic `GMTM`, then version int |
| `map_worldgen.bin` | `WorldGenParams.save()/.load()` | Magic `WGEN`, seed string, then **last 16 bytes = 4 big-endian ints**: `minXCell, minYCell, maxXCell, maxYCell`. Default build-42 world is `-250,-250,250,250` |
| `entity_data.bin` | `GameEntityManager.Save()` / `.load(int)` | B42 ECS layer: `MetaEntity` objects via `MetaEntitySystem.saveMetaEntities()` (craft, furnace, fluid containers) |
| `id_manager_data.bin` | `ObjectIDManager.save(DataOutputStream)` | **Only `lastId` per `ObjectIDType`** — see the trap below |
| `iTrack.bin` | `InstanceTracker.save()/.load()` | Debug counters only (`ITEMS`, `CONTAINERS`, `STATS`). Not world state |
| `WorldDictionary.bin` | `DictionaryData.save()/.load()` | Maps item/entity/sprite names to compact numeric IDs used by the other binaries. `WorldDictionaryLog.lua` / `WorldDictionaryReadable.lua` are its text side-products (`saveAsText`) |
| `gos_*.bin` | Global object systems | `gos_farming`, `gos_campfire`, `gos_trap`, `gos_feedingTrough`, `gos_rainbarrel`, plus mod ones. Count occurrences of a per-object key (e.g. `objectName`) to size them |
| `players.db`, `vehicles.db` | SQLite | `networkPlayers(id,world,username,name,steamid,x,y,z,worldversion,data,isDead)`; `vehicles(id,wx,wy,x,y,inMeta,worldversion,data)` |
| `map_visited_server/<user>.zip` | `WorldMapVisitedServer` | Per-player fog of war — full layout below |
| `erosion.ini` | Erosion system | Seeds, `time.*`, `season.*` |
| `blam/` | **Not identified** | Not found in the searched classes. Do not guess |

Read a save's own `map_worldgen.bin` rather than assuming the default bounds. Every geometry below
derives from those four ints.

## Trap: `id_manager_data.bin` counters are not object counts

Layout: `int version`, `byte entryCount`, then per entry `byte type` + `long lastId`.
`ObjectIDType` values seen: `2=Item`, `3=Container`, `4=DeadBody`, `5=Vehicle`.

The shutdown log line comes from `ObjectIDType.toString()`, called by `ObjectIDManager.save()`:

```
ObjectID type=DeadBody last=19597 new=0
```

`lastId` only ever grows — `ObjectIDType.allocateID()` does `++this.lastId; ++this.countNewId;`, and
`ObjectIDManager.remove()` drops the object from `idToObjectMap` without touching `lastId`. On load
the engine adds a **+100 safety margin** against crash-induced ID collisions.

**So `last=` is the count of IDs ever handed out since world start, not what exists now.** Ambient
corpses generated by `IsoChunk.AddCorpses()` are counted too. Verify with a known quantity: if
`Vehicle last=9100` but `SELECT COUNT(*) FROM vehicles` returns 3083, the counter is not a census.

`countNewId` (`new=`) resets to 0 on every save and on load. The live count exists only as
`ObjectIDType.DeadBody.getObjects().size()`, which is never persisted or logged. `CorpseCount` is
likewise in-memory only, rebuilt on `chunkLoaded()`.

## `map_visited_server/<user>.zip` — per-player fog of war

Two separate systems exist; do not confuse them:

- **`WorldMapVisited`** — client / single-player. Writes `map_visited.bin` with a **28-byte** header
  (`saveHeader()`: `249,2,minX,minY,maxX,maxY,8`). Does not touch `map_visited_server/`.
- **`WorldMapVisitedServer`** — dedicated server, one instance, `HashMap<String, byte[]> dictionary`
  keyed by username. Owns `map_visited_server/`.

Methods: `getFolderName()`, `loadUser(IConnection)`, `saveUser(String)`, `unloadUser(String)`
(on disconnect), `sendRequestData(IConnection, ByteBufferWriter)`, `update()` (marks the area around
each connected player every tick via `WorldMapVisited.updatePlayer`), `deleteUser(String)`.

### Container and header

A real ZIP holding **exactly one entry**, named as the sanitized username (`FileName.sanitize`), no
extension. `saveUser()` writes `out.putInt(IsoWorld.getWorldVersion())` and then the raw payload —
so the header here is **4 bytes only**, big-endian, `249` on build 42.20.x. The 28-byte header
belongs to the client file, not this one. `loadUser()` reads the int but never validates it.

### Geometry

Constants on `WorldMapVisited`: `SQUARES_PER_CELL=256`, `SQUARES_PER_UNIT=32`, `BITS_PER_UNIT=2`,
`UNITS_PER_BYTE=4`, `BIT_VISITED=1`, `BIT_KNOWN=2`, `UNITS_PER_CELL=8`.

```
widthInCells  = maxXCell - minXCell + 1        # from map_worldgen.bin
heightInCells = maxYCell - minYCell + 1
span          = widthInCells * 8 / 4           # bytes per unit row
payloadBytes  = span * heightInCells * 8
fileBytes     = payloadBytes + 4
```

Default build-42 world (`±250`): `widthInCells = 501`, `span = 1002`,
`payload = 1002 * 4008 = 4,016,016`, **file = 4,016,020 bytes**.

### Bit packing

Row-major by unit-Y, 4 x-units per byte, 2 bits each, **low bits = lowest x-unit**:

```java
byte b = visited[x/4 + y*span];
int flags = (b >> (x%4 * 2)) & 3;
```

| flags | meaning |
|---|---|
| 0 | unexplored |
| 1 | visited |
| 2 | known (drawn on map / seen at distance) |
| 3 | visited + known |

All 256 byte values are legal — every byte is four independent 2-bit fields. Common values in real
files: `0xAA` = 4× known-only (distance halo), `0xFF` = 4× visited+known (walked), `0xF0`/`0xFC`/
`0x3F`/`0xC0`/`0x03` = partial-byte boundaries of the same patterns.

Square → byte offset (`normalizeX/Y` subtracts `minXCell*256`, then divides by 32):

```python
ux = (squareX - minXCell*256) // 32
uy = (squareY - minYCell*256) // 32
byteIndex = ux//4 + uy*span        # + 4 for the file header
flags = (payload[byteIndex] >> ((ux % 4) * 2)) & 3
```

### No checksum, no length field

Neither exists in this format. The only structural value is the leading version int.

### Revealing the whole map

There is **no supported way** on a dedicated server. Verified, not assumed:

- **`Map.MapAllKnown`** (`SandboxOptions$Map.mapAllKnown`, default `false`) is referenced in exactly
  one place across all 5,080 `zombie.*` classes: `WorldMapVisited.getInstance()`, the client class.
  It calls `setKnownInCells(...)` — **KNOWN bit only** — once, when the instance is created. The
  field is absent from `WorldMapVisitedServer` bytecode entirely. On a dedicated server it therefore
  does nothing to `map_visited_server/*.zip`, and it never applies retroactively to an existing
  character. The sandbox comment "on starting the game" is literal.
- **No RCON command, no admin command, no Lua API.** All 68 command classes checked; no
  `Visited`/`RevealMap`/`AllKnown` entry. Both classes carry `@UsedFromLua`, but no shipped
  `media/lua` file calls them and no global wraps them.
- **Deleting the zip resets to fully hidden, not revealed.** `loadUser()` falls back to
  `new byte[getVisitedLength()]` — all zero, and zero means unexplored.

So editing the binary is the only route: keep the 4-byte header, set every payload byte to `0xFF`,
keep the file size exact.

### Sync direction: server → client only

`WorldMapClient.worldMapLoaded()` sends `RequestDataPacket.RequestID.PlayerVisited`; the server
answers from its `dictionary` via `sendRequestData()`, deflated; the client inflates into its own
`visited` in `WorldMapVisited.receiveRequestData(bb)`. **No packet type or code path sends the
client's bitmap to the server.** A server-side edit cannot be overwritten by a connecting client.

**But the server holds a decompressed in-memory copy** in `dictionary` for every connected user and
writes it back in `saveUser()`, called from `unloadUser()` (disconnect) and the save tick. Edit only
with the server stopped, or at minimum with that user disconnected — otherwise the in-memory copy
overwrites the edit on their next save or disconnect.

## Corpse removal

`SandboxOptions.hoursForCorpseRemoval` (`DoubleSandboxOption`, **default `-1.0`**), evaluated in
`IsoDeadBody.updateBodies()`:

```java
float h = (float)SandboxOptions.instance.hoursForCorpseRemoval.getValue();
if (h <= 0.0f) return;                    // disabled at -1 or 0
```

Rot stages use `h / 3.0f` for humans, `h / 4.0f` for animals; removal once
`age >= h` (plus a skeleton rot-stage bonus).

**Player corpses are skipped** unless `RemovePlayerCorpsesOnCorpseRemoval=true` in the server INI
(default `false`) — condition
`!ServerOptions.instance.removePlayerCorpsesOnCorpseRemoval.getValue() && !body.wasZombie`.

**It runs every tick, not only on chunk load.** `updateBodies()` is called from
`IsoCell.updateInternal()` inside the profiler block `"Update Dead Bodies"`, server and client alike.
`IsoChunk.load` only calls `AddCorpses()`, which *generates* ambient corpses. Corpses in unloaded
chunks are not iterated, so a cell must be loaded for its corpses to age out.

Corpses persist as ordinary moving objects **inside `map/<X>/<Y>.bin`** — `IsoDeadBody.save()` calls
`super.save()` up the `IsoMovingObject` chain, then `getObjectID().save(output)`. There is no separate
corpse file, no marker header, and no plaintext type name, so counting them from disk means counting
their **worn clothing** (`Base.Socks_Ankle`, `Base.Briefs_White`, `Base.Shoes_*`, `Base.Bra_*`) and
accepting that wardrobes contain the same items. Note that `ZombieThumpGeneric` is a **furniture
sound attribute**, not a corpse marker.

## Cost drivers

- **`IsoDeadBody.updateBodies()`** iterates every loaded `DeadBody` each tick via
  `ObjectIDType.DeadBody.getObjects()` — linear in loaded corpses. Returns immediately when the
  option is `<= 0`.
- **`IsoMetaGrid.load()`** reads `map_meta.bin` through the shared `SliceY.SliceBuffer`, then loops
  the **whole** grid (`for y < height; for x < width`) calling `compact()` per cell. Scales with map
  size, not with visited area — a fixed start cost on a large custom map.
- **`MapFiles`** builds `bgHasCell` / `bgHasCell300` boolean grids across the full map extent at
  startup. Also map-size bound.
- **`MapCollisionData`** runs on its own daemon thread (`Sync.fps=10`); `save()` busy-waits the main
  thread (`while (this.thread.save) Thread.sleep(5)`) until the native save finishes.
- **File count, not byte count, dominates backups.** `BackupsOnStart` zips the whole save folder.
  A `map/` with hundreds of thousands of ~2.6 KB chunk files costs roughly a millisecond per file:
  360,496 files measured at 436,482 ms compression — 11 minutes, with `BackupsCount` copies retained.
  Chunk files are written on first visit and **never deleted**, so this only grows.

`AdvancedAnimator` was **not** verified as a chunk-load cost driver; its `visitFileFailed` /
`NoSuchFileException` spam at `f:0` is mods lacking `media/AnimSets` and `media/actiongroups`, and
costs startup time only.
