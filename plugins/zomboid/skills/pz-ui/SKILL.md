# Project Zomboid UI

Every in-game window, button and panel is Lua, in `media/lua/client/ISUI` — **296 classes, 4,720
methods, 87,624 lines**. There is no UI markup and no layout engine: a widget positions its children
by pixel coordinates in its own `createChildren`, and draws itself in `render`. Building your own UI
means deriving from one of these classes and doing the same.

**UI is client-side only.** A file under `client/` is where a panel belongs; the same code under
`server/` never runs on a dedicated server. A panel that needs server data asks for it over a command
— call the Skill tool with `pz-multiplayer`.

## Building your own panel

Derive, construct, create children, add to the manager:

```lua
MyPanel = ISPanel:derive("MyPanel")

function MyPanel:new(x, y, width, height)
    local o = ISPanel.new(self, x, y, width, height)
    o.backgroundColor = { r = 0, g = 0, b = 0, a = 0.8 }
    o.borderColor     = { r = 1, g = 1, b = 1, a = 0.4 }
    o.moveWithMouse   = true
    return o
end

function MyPanel:createChildren()
    ISPanel.createChildren(self)
    self.btn = ISButton:new(10, 10, 100, 25, "Close", self, MyPanel.onClose)
    self.btn:initialise()
    self:addChild(self.btn)
end

function MyPanel:render()
    ISPanel.render(self)
    self:drawText("Hello", 10, 45, 1, 1, 1, 1, UIFont.Small)
end

function MyPanel:onClose()
    self:removeFromUIManager()
end
```

Then show it: `local p = MyPanel:new(100, 100, 300, 200); p:initialise(); p:addToUIManager()`.

**The four methods that matter**, in call order: `new` builds the object, `initialise` runs once,
`createChildren` adds child widgets, then `prerender` and `render` run every frame while visible.
`update` runs every frame too, whether visible or not. Put no work in `render` — it is per-frame, per
panel.

**Always call the parent's version** of `createChildren`, `render` and `prerender`. Skipping it is
why a panel draws no background or loses its children.

Read a class's chain upward: deriving from `ISPanel` means also having everything `ISPanel` and `ISUIElement` define, and `ISUIElement` alone carries over 200 methods including every draw primitive.

The base classes to learn first, all in that file: **`ISUIElement`** (the root — geometry, children,
drawing, input, scrolling), **`ISPanel`** (a background and border, the usual parent for your own
widgets), **`ISCollapsableWindow`** (a titled, movable, resizable window), **`ISPanelJoypad`** (a
panel with controller navigation), **`ISButton`**, **`ISComboBox`**, **`ISScrollingListBox`**,
**`ISTextEntryBox`**, **`ISRichTextPanel`**, **`ISContextMenu`**, **`ISToolTip`**.

## Context menus, tooltips and the map

- **A context menu entry** is added by handling the relevant event rather than by subclassing;
  `pz-events` carries the event names and their arguments, and `ISContextMenu` in the widget index
  carries the API for adding options and submenus.
- **The in-game map** is its own subsystem: `media/lua/client/Map` on the Lua side and
  `zombie.worldMap` on the Java side, with 120 types and 1,288 members. For overlays and markers,
  read `ZOMBIE-WORLDMAP.md` through `pz-java-api`, and `AnnotatedMapOverlay` in the widget index —
  it derives from `ISPanel` and is the game's own example of drawing over the map.
- **Drawing in the world** rather than on the UI layer is a different mechanism from a panel. The
  world coordinate to screen coordinate conversion belongs to `pz-world`.

## Related

Call the Skill tool with "pz-lua-api" for the class system these widgets use and the override
patterns, "pz-java-api" for the Java side including `zombie.worldMap` and the text and texture
primitives, "pz-events" for the events a UI hooks, and "pz-world" for world-to-screen coordinates.
