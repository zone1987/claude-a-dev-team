# Project Zomboid Lua API

Project Zomboid ships **1,395 Lua files, 439,296 lines**, under `media/lua`. That code is both the
game's implementation and the best documentation of its own API: how an argument is meant, what the
idiom is, which function to call. This skill indexes it and carries the patterns for changing it.

## The three directories decide where code runs

- **`client/`** — the local player's game: UI, input, rendering, context menus. On a dedicated
  server this never executes.
- **`server/`** — authority: the world, containers, players, commands. On a client this never
  executes.
- **`shared/`** — loaded by both: definitions, helpers, class declarations.

Singleplayer runs client and server in one process, which is why a side mistake works there and
fails on a dedicated server. Decide the side for every file before writing it.

**Load order is alphabetical within each directory**, and `shared/` loads before the other two. A
file that depends on another must sort after it or use `require`. Two mods touching the same
function resolve by load order, so the later mod wins — which is a fact to design around, not to
rely on.

## Finding and changing game code

The index is the first stop, but grep over the installation settles intent:

```bash
J="$HOME/Library/Application Support/Steam/steamapps/common/ProjectZomboid/Project Zomboid.app/Contents/Java"
grep -rn "getSpecificPlayer" "$J/media/lua" | head
```

Reading a real callsite tells you an argument's meaning in a way a signature cannot.

When changing base-game behaviour, prefer in this order, because each step down is more likely to
break on a game update:

1. **An event.** Nothing is overridden, so nothing conflicts. Call the Skill tool with `pz-events`.
2. **A wrapper that calls through.** Keep the original in a local and call it, so other mods in the
   chain still run:
   ```lua
   local original = ISInventoryPane.onRightMouseUp
   function ISInventoryPane:onRightMouseUp(x, y)
       original(self, x, y)
       -- your addition
   end
   ```
3. **A full replacement.** Only when the original must not run. This silently discards any other
   mod's wrapper, and it breaks whenever the game changes that function.

## Kahlua, not standard Lua

The interpreter is **Kahlua**, a Java implementation, not reference Lua. That matters in practice:
Java objects arrive as userdata with their Java methods, numbers cross the boundary through explicit
converters, and parts of the standard library that a Lua programmer expects may be absent. Before
relying on a standard-library function, check that the game's own code uses it — that is the
reliable test. `zombie.Lua` in the Java reference carries the converters.
