# Project Zomboid vehicles

A vehicle is a script block like an item, but composed: a `vehicle` block references a model, a set
of `part` blocks, `wheel` blocks and `passenger` positions, and inherits shared values from a
`template`. That composition is why a vehicle definition looks short — most of it comes from the
template it names.

At runtime a vehicle is a `zombie.vehicles.BaseVehicle`, which carries its position, engine state,
fuel, parts and occupants.

its frequency and its legal values — call the Skill tool with `pz-items` and read its
`PROPERTY-CATALOGUE.md`. For the runtime API, `pz-java-api` carries `zombie.vehicles` with 75 types.

## Working with vehicles

- **A vehicle needs a model and a distribution** as well as a script, so a mod adding one ships more
  than a definition. Read an existing vehicle's files as the template.
- **Parts have conditions and skill gates.** Installation and removal go through timed actions, and
  the mechanic skill governs both.
- **Position and state are server-authoritative.** A client reading a vehicle's position is reading a
  synced copy; writing to it belongs server-side.

## Related

Call the Skill tool with "pz-items" for the property catalogue and the parts that are also items,
"pz-java-api" for `BaseVehicle` and the vehicle classes, and "pz-lua-api" for the vehicle Lua.
