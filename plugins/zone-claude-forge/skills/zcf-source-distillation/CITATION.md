# Citing a source

Knowledge without a citation cannot be maintained: nobody can tell whether it is still true, and
nobody knows what to re-read when the upstream changes. Rules: `SRC-01` to `SRC-06`.

## What a citation must let a reader do

Three things, and a citation that fails any of them is decoration:

1. **Check a claim**: follow the link and find the same statement.
2. **Judge the age**: a version, sha or date, not only a URL.
3. **Plan a refresh**: know which upstream file or page feeds which reference file.

## Three places, three forms

**In `SKILL.md`**, a closing `## Source` section naming the upstream, the version or hash, and the
date. `SRC-01`, `SRC-06`

```markdown
## Source

Distilled from the [Ventrata OCTO API specification](https://docs.ventrata.com) —
`openapi.yaml` 3.0.3, sha256 `d7bec97a…`, retrieved 2026-08-20.
Reference files in this directory are generated; see `scripts/extract_spec.py`.
```

**In a generated file**, a stamp on line 1, so a later hand edit is visible: `SRC-03`

```markdown
<!-- generated by scripts/extract_spec.py from openapi.yaml sha256:d7bec97a — do not edit above the prose marker -->
```

**In a hand-written reference**, the **specific page** rather than the site root. `SRC-02`

```markdown
Source: https://docs.ventrata.com/capabilities/pricing, retrieved 2026-08-20.
```

`docs.ventrata.com` alone is not a citation of anything: it cannot be checked, because the claim
could be on any of 39 pages.

**In the plugin `README.md`**, the canonical source for the whole plugin plus the rights holder of the
original documentation. This marketplace is public, so crediting the source is both an accuracy
measure and a courtesy.

## Never cite

- **A path that exists only on the author's machine.** Embed the knowledge, cite the origin.
- **An upstream path the user's project does not contain.** A reference to `vendor/…` in a plugin the
  reader installed from a marketplace resolves to nothing.
- **A third-party write-up** where the original exists. It dates silently and cannot be re-checked
  against the thing it describes. `SRC-05`

## A version is not optional

`https://code.claude.com/docs/en/skills` tells a reader where to look and nothing about whether the
claim still holds. The same URL with `retrieved 2026-08-21` tells them how much to trust it. For a
repository, the commit sha is better than a date, because it is exact.

## Verify the citations, both directions

Every rule or claim has a source, **and** every quotation appears verbatim on the page it cites. The
second direction catches the plausible-sounding claim nobody can trace, the same asymmetry that makes
a reverse field check worth more than a forward one.

```bash
python3 scripts/verify_sources.py --check              # structure, offline
python3 scripts/verify_sources.py --pages /tmp/mirror   # quotations, against a mirror
```

Normalise before comparing, or the check produces false negatives that teach the reader to distrust a
passing run: a renderer turns straight quotes curly, and a page keeps Markdown inline code and links
around identifiers a quotation writes bare.
